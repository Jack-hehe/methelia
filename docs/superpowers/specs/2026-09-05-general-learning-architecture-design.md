# Methelia：通用課程生成架構

日期：2026-09-05

狀態：產品方向已在對話確認；本文件的詳細架構待使用者審閱。這是目標設計，不是已實作能力清單。

共同詞彙：[CONTEXT.md](../../../CONTEXT.md)。目前實作與限制仍以 [README.md](../../../README.md) 為準。

## 1. 產品目標與本次範圍

Methelia 建立的是可持續擴充的課程生成架構，不是一組寫好的 HTML 課程。使用者在首頁輸入 Learning Goal，系統規劃 Course Graph，再逐個 Learning Node 準備完整 Chapter Package，以預製的互動網頁呈現。

「You can learn everything」是產品願景：核心模型不綁定學科，也不要求每堂課都有程式碼、Terminal 或網站作品。它不是聲稱目前具備所有實作工具、能驗證所有領域的知識，或能保證任何模型輸出的教學都正確。

網站製作、Python 入門、Linux 檔案操作是第一批跨環境驗收案例，不是核心的科目白名單。概念型的非程式主題也必須能用同一個核心表示與呈現，無須修改 Course Graph 或播放器。

本輪先確立核心 Interface 與遷移順序。教學文案、細部游標節奏、元件美化可後續調整；會破壞資料、章節可用性或隔離規則的問題不能以「細節」為理由略過。

本文件取代舊 MVP 規格中的「核心僅支援網站」方向。現行單頁課程、固定底欄、右下角 Learning Map、右側節點資訊欄、手動翻頁、淺色預設及單一老師繼續保留。不能恢復舊規格的整章自動捲動、語音失敗擋住內容，或 Fish 自動重送。

## 2. 選定的方向與取捨

採用「學科無關的核心＋有明確能力的預製 Module」，沿用本機模組化單體，不先拆微服務或建立外掛市場。

- 只放寬生成提示，改動較小，但不能解除 Terminal、檔案格式與網站預覽的綁定，也不能解決模型選到不能執行的功能。
- 為每一科建立獨立生成流程，可快速製作個別展示，但課程進度、語音與錯誤處理會重複，後續難以維持一致。
- 共用 Protocol、規劃、播放與進度，讓預製教學工具透過清楚的 Seam 接入，需要先整理既有耦合，但新主題不必另做播放器。採用此方向。

不設計能生成任意 UI 的通用 DSL。模型選擇的是受限的內容、版型與操作；每個可執行能力背後都有實際的 Implementation。

## 3. 固定與生成的責任

| 項目                                 | 負責者               | 規則                                                         |
| ------------------------------------ | -------------------- | ------------------------------------------------------------ |
| 學習目標、課程路徑、節點數量         | Course Planner       | 根據目標與 Generation Policy 產生，不用固定課程冒充          |
| 頁面內容、範例、題目、Chapter Script | Node Generator       | 一次生成完整小章節，與指定節點目標一致                       |
| 版面結構、響應式行為與視覺規則       | Component Template   | 使用預製版型與有上限的內容欄位                               |
| 編輯器、Terminal、預覽、測驗等操作   | Learning Component   | 模型提供設定，不提供元件實作程式                             |
| 程式執行、檔案操作與結果             | Learning Environment | 只能使用已啟用的 Adapter，不能在主機任意執行                 |
| 練習完成判定                         | 固定 evaluator       | 檢查可驗證的證據，不信任模型或前端自稱完成                   |
| 語音、字幕、操作同步                 | Narration Module     | 依已保存的 script 與 cue references 準備，不在播放中生成文字 |

學習用的範例程式碼可以由模型生成；它和 Methelia 的介面程式碼、驗證器、執行環境必須分開。範例只能在授權的隔離環境中使用。

## 4. 核心 Module 與 Interface

| Module                        | 輸入                                                             | 輸出與主要責任                                                     |
| ----------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| Course planning               | Learning Goal、程度、語言、Generation Policy、可用能力清單       | 完整 Course Graph 或需要澄清／缺少能力的結構化結果                 |
| Chapter preparation           | 目標節點、圖形與先修脈絡、已完成目標、相關工作材料、可用能力版本 | 經驗證且不可變的 Chapter Package，或明確的失敗結果                 |
| Protocol & capability catalog | 版本化的圖形／章節資料、已註冊的能力定義                         | 格式、相容性、引用與資源限制檢查；不依賴模型供應商、React 或資料庫 |
| Course presentation           | 有效 Chapter Package、已保存的互動狀態、Narration Cursor         | 預製元件呈現與具名操作；不負責規劃內容或直接呼叫模型               |
| Learning environment          | 環境 ID、工作材料版本、已授權的操作                              | 有上限的輸出、工作材料變更與驗證證據；不包含課程 UI 排版           |
| Narration                     | package/script 身分、頁面 script、老師設定                       | Page Audio Tracks、字幕及可驗證的 cue mapping                      |
| Learning progress & revisions | 有效練習證據、導覽事件、使用者確認的 Branch Preview              | 學習進度、下一個可進入的節點、原子化 Graph Revision                |

生成供應商與 Fish 留在 server Adapter。共用元件的定義與輸入驗證集中管理，前端渲染註冊表使用相同的 ID／版本；不讓前端與提示各自維護一份不一致的能力清單。

先利用已經存在的概念元件和網站實作兩種不同需求建立真實 Seam，再增加 Python、Linux Adapter；不為想像中的每一科預先建立空殼 Module。

## 5. Learning Goal、Course Graph 與關卡規則

首頁保持一個主要輸入，不增加冗長的設定表單。程度與語言有預設值；只有缺少的資訊會明顯改變學習目標或所需能力時才詢問使用者。

- 原始 Learning Goal 保留。不得把「學 Python」無聲轉成「用 HTML 介紹 Python」。
- Course Planner 先產生完整的路徑、每個節點的目標、先修關係及預估時間，不同時生成所有詳細課程。
- Learning Node 就是一個小章節／一關；Lesson Section 是該關的一頁，不再混用兩者計算進度。
- 關卡數、頁數、文案長度與預估時長由共用 Generation Policy 控制。模型可以在上限內依需求調整，不固定五關或每關三頁。
- 第一輪遷移沿用現有保守規模：規劃通常 4–9 個節點、每章通常 3–6 頁，硬上限 50 個節點、每章 10 頁；它們是可調整的生成限制，不是科目或課程結構的定義。
- 每個完整目標路徑有可描述的終點。不是所有終點都必須是「匯出網站」，也不能把看完頁面等同掌握實作技能。
- 第一輪仍採一條可確定下一步的學習路徑，補強以 detour 串入再接回，不同時引入任意多路徑排程或全新 Graph 編輯器。

Node Generator 必須拿到相關 Course Graph 脈絡，不只拿到孤立的節點標題。輸入至少包含目前目標、先修目標與已完成脈絡、後續銜接目標及所需工作材料，降低重複教學與突然使用未介紹概念的風險。

「可以教一個概念」與「可以執行該領域的所有操作」分開表示。缺少必要能力時，先說明限制並請使用者確認調整目標；不能自行降級後仍聲稱原目標已達成。

## 6. Chapter Package、版型與能力協定

保留既有 Chapter Package 概念，新增能力採明確的新版本。以下是需要固定的契約，而非允許任意欄位的資料袋：

- 身分與相容性：protocol version、package ID、node binding、內容及生成脈絡指紋；ID 與版本由系統驗證，不由模型決定覆寫哪一筆資料。
- Lesson Sections：固定順序、穩定 ID、每頁一個主要目標、允許的 intent、Template ID／版本與具名 slots。
- Learning Components：每個 instance 有 ID、type／版本及該類型專屬的 props schema。模板宣告可容納的 slot、元件種類與數量，不能任意嵌套 UI。
- Learning Environment：只在需要實作時綁定，宣告環境 ID／版本、workspace 與必要能力。一般講解與測驗不得因此建立空白 Terminal。
- 準備資料：檔案與其他工作材料的有上限初始資料、路徑規則、非破壞性的合併方式。
- 教學操作：以元件 ID、具名目標及封閉的操作類型描述，例如選取比較項目、突出顯示一段程式或執行示範副本。禁止傳入任意 JS、CSS selector 或畫面座標來取得控制權。
- 完成條件：指定已註冊 evaluator、目標及輸入；本次 v2 每個節點至少有一個可檢查的 checkpoint。概念型節點可用理解題，並不因此要求程式實作。
- Chapter Script：每頁一筆完整解說與穩定 section reference，可引用已驗證的互動目標。script 不依賴使用者自動翻頁或預設已完成操作。

Registry 中每個能力定義包含：用途說明、版本、props schema、可用操作、可提供的證據、環境需求、內容與資源上限，以及相容的版型。模型取得的是這份清單的資料描述，不能取得伺服器憑證或自訂 Implementation。

固定版型先涵蓋重點說明、比較、步驟、實作、理解檢查。沿用可用的既有元件，逐步抽離特定教材；像 HTML/CSS/JavaScript 的特殊互動必須是明確的元件類型／設定，不能靠比對教材標題觸發。

「一致」指導覽、操作、字級層級、內容密度與錯誤行為可預期，不是所有課程長得完全一樣。程式教學、圖解與比較可以使用不同版型。

## 7. Learning Environment 與實作畫面

Terminal 是輸入／輸出介面；IDE 是編輯工作材料的介面；是否能執行 Python 或 shell 由環境決定。這三者不可以再被同一個「Terminal 模式」代表。

| 驗證案例       | 實作組合                            | 能力界線                                                                    |
| -------------- | ----------------------------------- | --------------------------------------------------------------------------- |
| 網站製作       | 檔案列表、IDE、即時 Browser Preview | HTML/CSS/browser JS；預設直接編輯，不要求先開 Terminal                      |
| Python 入門    | IDE、執行按鈕、標準輸出／錯誤       | 必須接真正可執行 Python 的隔離 Adapter；未接好前不能宣告可執行              |
| Linux 檔案操作 | Terminal、目錄／檔案狀態            | 明確區分受限教學環境與真正 Linux shell；目前的網站預覽轉接器不算 Linux 支援 |
| 非程式概念     | 說明、比較或步驟、理解檢查          | 不建立程式碼工作區、不要求 Terminal 或網站輸出                              |

環境透過小型 Interface 提供能力說明、setup 驗證、非破壞性初始化、允許的操作及結果驗證。既有虛擬命令環境、網站預覽與未來 Python 實作分別是 Adapter，不把 shell 指令判斷散落到模型提示、Protocol Validator 和播放器。

所有環境遵守共同規則：

1. 工作材料依 learner/course/workspace 隔離。概念型章節的 workspace 可不存在。
2. 套用、執行與驗證前處理未存草稿及版本衝突；禁止無聲覆寫。
3. 初始化與 Protocol Validator 使用同一套路徑規則。子目錄要正確建立或在準備階段拒絕，不能驗證通過後被略過。
4. 示範使用獨立副本，不完成學員 checkpoint，也不修改學員作品。播放與重播不自動執行學員工作區中的操作。
5. 範例和練習在啟用前使用同一個 Adapter 做可用性檢查。實際練習結果帶有 operation、package 與 workspace 版本身分，不能用過期輸出完成新練習。
6. 新增可執行 Adapter 必須先定義時限、記憶體／輸出上限、停止與重設、網路政策及資料隔離。不得把生成程式交給 Methelia 主機 shell。

若未來章節需要更動現有檔案，準備階段必須驗證其與實際工作材料的相容性。遇到衝突保持學員檔案，準備新的相容 package 或請使用者處理；不能靠覆寫舊作品讓示範看起來成功。

## 8. 生成、驗證與發布

流程分成三個互不冒充的成果：完整 Course Graph、完整 Chapter Package、完整章節語音。

1. 提交目標建立可追蹤且去重的規劃工作，規劃失敗保留原目標供重試。
2. Graph 通過引用、先修與路徑驗證後保存並顯示 Learning Map。
3. 優先準備目前 Learning Node，低優先預取下一個節點。每次準備一整個 Chapter Package，不能向正在看的頁面插入模型輸出。
4. 驗證結構、版本、能力、操作、資料初始化、練習可用性與版面上限，通過後才原子發布。
5. 內容發布即可閱讀、互動；語音工作獨立處理，不阻止下一章內容生成。
6. 完成有效 checkpoint 後才更新節點進度與進入下一章。翻頁、跳音訊位置或示範完成不是學員完成證據。

內容狀態為 queued → generating → validating → ready，失敗可進入 failed；已 ready 的 package 保持不可變。修訂以新 package ID 發布，不能修改學員已開始的 package。

驗證分層，但不建立第二套可自由寫程式的 AI 驗證器：

- 結構：schema、版本、ID、順序與引用完整。
- 能力：Template、Component、Environment、操作與 evaluator 相容且真的可用。
- 準備：檔案建立、示範重播、練習目標存在、受限操作可執行。
- 呈現：標題、本文、選項、程式區塊各自有不同長度上限，超出則在發布前修復，不靠無限縮小字體。
- 教學：目標對應、必要先修與 checkpoint 覆蓋；範例、答案和解說需透過生成驗收抽查。

格式／可用性驗證不等於學科內容必然正確。專業知識來源、特定領域的內容審查與更多評量方式是後續擴充，不在本輪聲稱已解決。

模型格式錯誤最多修復兩次，每次仍提交完整章節供驗證。仍失敗時保留有效圖形和目前課程，提供具體可重試狀態，不用固定 HTML 課程代替生成結果。

## 9. 語音與播放協定

一個小章節一次備妥全部 script；每個 Lesson Section 的 script 各送一次完整 Fish 請求，不逐句生成，也不讓播放途中產生新講稿。

- Narration Module 不依賴 HTML、Terminal 或特定元件；使用穩定的 section/component references。
- 內容與語音使用不同工作種類及有上限的獨立執行通道。慢速或失敗的 TTS 不能佔住內容生成通道；不以移除 await、無限制並行來達成。
- 語音狀態區分 not_requested、queued、generating、ready、failed。`pending` 遷移時只能對應確實存在的工作，不能讓按鈕永久等待一個未排程的工作。
- 新生成課程的目前章節，內容發布後自動排程其語音；純內容預取不自動為未到達的章節付語音費。使用者進入該章後再排程，或明確要求提前準備。
- 固定體驗課程維持手動準備語音，避免不知情的付費呼叫。將來可加設定，但核心不需要改變。
- 音檔逐頁保存；該章所有頁面音檔與字幕可用後才開放語音播放。語音失敗仍可使用完整課程，不再加入強制文字模式閘門。
- 每頁播放結束停在原頁。翻頁先停止音訊，不自動播放下一頁；Learning Map 與 Help Drawer 維持暫停規則。
- 對齊使用服務實際回傳資料。沒有精確 cue 的頁面採明確的頁級同步，不捏造逐字時間或語意級游標同步。
- 快取與工作去重至少綁定 package、section、精確 script、voice 與 synthesis settings／Adapter 版本。只重用確認完整保存且身分相符的成果。
- 逾時、斷線、回應錯誤或對齊失敗不自動重送 Fish；手動重試提示可能再次計費。跨供應商的 exactly-once 不作保證。

核心只保留一位老師。未提供 avatar 素材時不新增裝飾性角色 placeholder。

## 10. 進度、補強與失效控制

Course Graph 的結構版本、Chapter Package 內容、學員 workspace 與播放狀態分開保存。拖動 Learning Map Node 仍只是視覺位置，不改依賴。

Help Drawer 可以回答小問題或提出 Support Node，但不能直接改圖、執行工具或更動當前講稿。新增節點仍經過 preview → confirm，插入當前小章節之後，學完接回原本的 Rejoin Point。

未來 package 的重用不能只比較 node ID；需比較目標、相關先修脈絡、能力版本與準備資料要求。工作執行及成果發布時都核對現行綁定，過期結果不能成為新路徑的章節。

不要因為 workspace 每次打字或修改無關節點，就重算整套課程。只使受影響的未來準備失效，保留已完成及正在學習的 package。章節啟用前再驗證其工作材料要求與最新已保存資料相容。

## 11. 遷移與第一批交付

保留現有 UI、資料庫、課程與音訊，不整批重寫。README 不得因為寫好新設計就宣稱已支援 Python、Linux 或任意科目實作。

第一個可獨立實作的範圍是「通用契約與現有能力拆分」：

1. 建立 subject-independent 的 Generation Policy、版本化 Protocol 與能力註冊表，保留舊版讀取與驗證。新增資料採明確的 v2；未知版本明確失敗，不偷偷當作 v1。
2. 將現有概念／測驗、網站 IDE／preview、受限 Terminal 接成已註冊能力；移除核心對網站標題與 Terminal 畫面的隱含依賴。
3. 統一準備資料、操作與完成條件的驗證入口，涵蓋目前已確認的路徑與命令不一致問題。
4. 讓首頁 live 規劃與 Node Generator 使用相同能力清單及圖形脈絡。可透過基礎概念元件教授其他主題，但不承諾缺少環境的實作目標。
5. 使用同一播放器驗證網站課程與不需要 workspace 的概念課程。以不同內容／ID 驗證，不依靠教材字串觸發互動。

第一批後續交付依序為：

- 語音工作與內容工作解耦，保留逐頁 script、音檔、重試與快取規則。
- 增加 Python 入門及 Linux 檔案操作所需的實際 Adapter，分別驗證，不先假造成功輸出。
- 由首頁輸入網站、Python、Linux 目標，完成三個真正生成的端到端 demo。
- PDF 講義使用同一 Chapter Package 的內容與獨立 print renderer，將互動轉成步驟、範例與練習說明；不重新生成另一份可能不一致的教材。PDF 匯出不納入第一個實作範圍。

這些交付共用整體架構，但各自有獨立驗收，不把完整 OS、每個科目的專用元件、PDF、登入與公開部署塞進同一次重構。

舊 package、已存語音與學員作品保持不變；讀取舊資料不能觸發重新生成、重新計費或以新示範內容取代。舊的 completed/progress ID 必須仍可解析。

## 12. 驗收原則

架構驗收優先檢查跨主題與跨 Module 的契約：

- 同一核心能表示網站、Python、Linux 與非程式概念的目標；輸入不是一個固定課程選單。
- 概念課程不強制 workspace；網站編輯不強制 Terminal；不具備 Python／Linux 環境時明確拒絕執行承諾。
- 相同元件用不同的內容、標題與 ID 仍能操作。加入新的已實作能力不需要重寫 Course Graph、語音或播放器導覽。
- 無效的檔案、命令、操作引用、版本、練習條件、過長內容，在章節發布前被攔下；成功示範不能冒充學員完成。
- 語音暫停、失敗或重試不改動課程內容；慢速語音不阻塞下一章內容生成。
- 新增補強節點後，當前課程穩定，未來失效工作不會回寫覆蓋，重開仍能恢復進度。
- v1 課程、逐頁與舊整章音軌都能讀取，不重寫使用者資料。

自動化採明確標記的本機 model／speech 測試替身；範例資料驗證和 live 驗收分開記錄。真正的 demo 必須由首頁提交全新目標、經模型產生圖形及章節、完成一次練習並恢復進度，不能以固定 fixture 或靜態畫面代替。

付費的模型／Fish 實測在實作驗收階段另行執行並記錄是否完成。這份設計文件及本輪檢查沒有觸發生成或語音合成。
