# Methelia 的學習體驗核心

這份文件記錄使用者確認的產品方向，作為後續課程生成與學習介面的設計準則。它描述目標，不代表目前功能已全部實現。

## 產品目的

將學習目標轉成可理解、可觀察、可嘗試、可驗證的學習經驗。使用者應能掌握關鍵概念、解釋變化並應用到新情境。閱讀量、翻頁數、點擊次數不應直接代表理解程度。

## 教學設計準則

1. **先定義要學會什麼。** 每個單元先列出一個核心能力、常見誤解，以及能觀察到的理解證據，再選擇呈現方式。
2. **精華保留必要推理。** 主畫面只呈現當下需要的重點；原因、例子、前置知識可按需展開。避免過度壓縮，讓學生只記結論卻無法理解。
3. **媒體承擔教學工作。** 圖像呈現結構與對照，動畫呈現時間與因果，實作讓學生改變條件並觀察結果，文字承擔命名與精確解釋。沒有教學用途的裝飾不應成為生成目標。
4. **以概念選活動。** 任務、操作、遊戲關卡與閱讀都可使用。互動需要讓學生作出有意義的判斷；遊戲的成功條件必須對應要學的能力。
5. **回饋緊接行為。** 指出學生剛才做了什麼、哪裡與目標不同、可以如何檢查。提供逐層提示與重試，避免直接揭露全部答案。
6. **讓理解可被看見。** 嘗試用預測、解釋、修改或新的小情境檢查理解。答錯可能是概念誤解、操作問題或題目表達不清，不可單憑一次錯誤武斷判定能力。
7. **依內容調整節奏。** 「觀察 → 預測 → 嘗試 → 解釋 → 應用」是可組合的教學動作，不是每個概念必須照抄的固定頁數與順序。
8. **維持情境連續。** 解說、動畫、操作與回饋圍繞同一個例子或作品逐步展開。使用者能隨時知道正在理解哪個概念、要觀察什麼，以及接下來可以做什麼。

## 具體例子：理解 Python 迴圈

學習目標：能預測一段簡單迴圈的執行次數與輸出。

- 同時顯示短程式、目前執行行、變數值和輸出，逐步執行時同步更新。
- 在一個關鍵步驟暫停，請學生預測下一個輸出。
- 學生改變次數，立即看到執行過程與結果如何變化。
- 用一句精確解釋整理迴圈的規則，必要時展開說明範圍的終點。
- 換一個小任務，讓學生獨立完成；錯誤回饋定位到具體步驟。

這個例子的互動重點是執行次數、變數和輸出之間的關係。單純按「下一步」或觀看動畫，不能自動當成已理解。

## 對生成系統的要求

生成器應先產生核心能力、誤解、教學活動及理解證據，再將活動映射到已支援的展示或操作能力。平台需要可重用且可組合的能力，以及誠實的能力邊界；遇到無法支援的模擬時，應選擇可用的教學活動，不虛構操作效果。

目前的閱讀頁、流程圖、示範打字與輸出對照是基礎。後續設計的重點是將它們整合成連續的學習活動，並讓評量與提示真正對應核心概念。上述迴圈同步視覺化與適應性提示仍屬待設計、待實作能力。
